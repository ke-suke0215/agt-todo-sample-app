# チャット付きTodoアプリ 設計メモ

## 目的

LLMをアプリに組み込む練習として、チャットからTodoを操作できるアプリを作る。GPTが自然文をどう解釈し、どの操作を選び、実行結果をどう伝えるかを試せる実験台にする。

TypeScriptで実装し、OpenAIのAPIキーを設定してGPTを使う。Todo一覧の右下にチャットを常時表示する。

## Webアプリの技術スタック

画面はReactとViteで実装し、プロトタイプの見た目をCSSで引き継ぐ。APIはHonoとNode.js 26 LTSで実装し、依存関係はnpmで管理する。画面とAPIは同じリポジトリに置き、開発時はViteから `/api` をHonoにプロキシする。SQLiteへの接続には `node:sqlite` を使う。

## ローカル実行とデータ保存

初版は1人で使う `localhost` 向けのアプリとする。画面とAPIを1つのTypeScriptアプリに置き、OpenAI APIキーはサーバー側の環境変数で設定する。初版の利用者は固定のローカルユーザーとし、ログイン画面は複数ユーザー対応時に検討する。

Todoと会話一覧用のメタデータはローカルのSQLiteに保存する。Todoと会話の両方に固定の所有者IDを持たせる。複数人に広げる際は、既存レコードを初期ユーザーに引き継ぎ、ユーザーテーブルと認証を追加し、検索・取得・更新・削除を認証済みユーザーの範囲に絞る。

将来の保存先候補にCloudflare D1を置く。SQLの変更はマイグレーションで管理し、SQLの呼び出しはサーバー側の保存処理に集める。D1に移す場合は、互換性を確認してSQL形式でデータを移行し、アプリの接続部分を変更する。 [D1のSQL互換性](https://developers.cloudflare.com/d1/sql-api/sql-statements/)・[D1へのインポート](https://developers.cloudflare.com/d1/best-practices/import-export-data/)

## エージェントの構成

TypeScript版 OpenAI Agents SDK と Conversations API を採用する。Agents SDK が内部で Responses API を呼び、ツールの実行と結果を渡した再呼び出しを管理する。ツールは画面からも使う共通のTodo処理を呼ぶ。

モデルは `gpt-6-luna` に固定する。チャット画面で推論レベルを選び、送信ごとに `reasoning.effort` に反映する。初期値はモデル既定の `medium` とし、`none`、`low`、`medium`、`high`、`xhigh`、`max` を選べるようにする。 [GPT-6 Lunaのモデル仕様](https://developers.openai.com/api/docs/models/gpt-6-luna)

会話本文・返答・ツールの引数と実行結果は OpenAI の Conversations API に保存する。履歴一覧のためにアプリが保存するのは会話ID・所有者ID・更新日時。過去の会話と実行詳細は OpenAI から取得して表示する。チャットの内容はアプリのデータベース、ブラウザーの永続ストレージ、ログ、SDKのトレースに記録しない。ログにはリクエストID、所要時間、ツール名、成否を記録する。 [Agents SDKのトレース設定](https://openai.github.io/openai-agents-js/guides/tracing/)

選定理由と比較候補は[エージェント技術選定の調査メモ](./todo-agent-research.md)を参照。

## Todoの項目

| 項目 | 初版の入力仕様案 |
| --- | --- |
| タイトル | 必須の1行テキスト |
| 詳細 | 任意の自由記述欄。複数行を入力でき、改行も保存する |
| ステータス | 「未着手」「進行中」「完了」から選択。省略時は「未着手」 |

## 初版の範囲

1. **画面からのTodo追加**  
   フォームで入力して追加すると、Todo一覧に反映される。
2. **チャットからのTodo追加**  
   GPTが依頼から値を取り出して `create_todo` を呼ぶ。アプリが作成に成功したら、Todo一覧に同じ項目が表示され、チャットに追加したことが返る。
3. **進行状況と実行詳細の表示**

   送信直後からチャット内に進行状況を表示する。ツールを呼んだら操作名を表示し、実行が終わったら結果を反映する。返答テキストは届いた分から表示する。実行詳細を開くと、GPTが渡した引数と既定値などが適用された保存結果を見比べられる。

初版の作成ツールは、依頼からタイトルを特定できる場合に実行する。「来週の件、タスクにして」のように何を登録するか特定できない場合は、タイトルを聞き返す。

### ストリーミングの設計

チャットへの送信はHTTP POSTで受け、同じレスポンスでサーバー送信イベント（SSE）を返す。Agents SDKのイベントを、モデルの応答待ち、ツール呼び出し、ツールの成否、返答テキストの差分、完了、エラーに対応づける。ツール呼び出しと結果は `call_id` で対応づけ、Todoが保存された時点で一覧を更新する。保存後にストリームが切れた場合は、一覧と履歴を取得し直せるようにする。同じ送信の再試行でTodoを重複作成しない。 [Agents SDKのストリーミング](https://openai.github.io/openai-agents-js/guides/streaming/)

ブラウザーは会話ごとに送信を一件ずつ行う。切断時は送信を自動でやり直さず、Todo一覧とOpenAIの会話履歴を再取得する。

画面では「応答を待っています」「Todoを追加しています」「Todoを追加しました」など、アプリが受け取った進行状況を表示する。OpenAIから推論の要約が返る場合は、要約として折りたたみ表示できるようにする。推論レベルは送信時に適用し、操作の進捗表示には実際のツールイベントを使う。 [OpenAIの推論要約](https://developers.openai.com/api/docs/guides/reasoning#reasoning-summaries)

### チャット操作の例

> 歯医者を予約する、を追加。詳細に「平日の夕方が希望」と入れて。

GPTが `create_todo` にタイトル「歯医者を予約する」と詳細「平日の夕方が希望」を渡す。アプリがステータス「未着手」を設定して保存する。チャットに「追加しました」と表示され、一覧に1件増える。

## 作成ツールの次に詰めること

- 初版の作成ツールに続いて、検索・内容確認・更新・削除を追加する。「牛乳のタスクを完了にして」のような依頼で、検索してから更新する流れや、候補が複数あるときの聞き返しを試す。
- チャットからの削除は、対象を表示して実行前に確認を取る案と、削除後に取り消せる案を、削除ツールの実装前に比較する。
